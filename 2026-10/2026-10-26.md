### 2026-10-26

## OpenJDK 인증서 취약점
- **개요**
  - https://nvd.nist.gov/vuln/detail/cve-2026-91403
  - 최근 인도 eMudhra 인증기관의 중간 CA 개인키가 복구 가능한 문제가 확인되었음
  - 해당 인증서를 신뢰하는 JVM 환경에서 영향을 주어 보안 업데이트 필요

- **어떤 위험성이 있는가?**
  - JVM은 이 도메인이 원래 어느 CA 인증서 쓰는지 모름
  - 신뢰 목록 (cacerts)에 있는 CA 아무거나 서명했으면 통과
  - 공격자는 `api.com` 인증서를 새로 만들어서 들이밀면, 진짜 서버가 어떤 CA 쓰는지 상관없이 호출
  - 브라우저의 경우, 등록되지 않은 인증서 거부해서 몰래 발급한 인증서 걸러내는데,
    - Java의 경우 이 검사하지 않아서 취약해
  - 공격자가 통신경로에 끼어들어 통신을 하이재킹할 때, 알맞은 인증서로 발급된 것인것 마냥 할수있음
    ```
    정상:   [우리 서버 JVM] ───────────────────────────> [진짜 api.partner.com]
    
    공격:   [우리 서버 JVM] ──> [공격자] ──────────────> [진짜 api.partner.com]
                                  │
                                  └ eMudhra 키로 서명한 "api.partner.com" 가짜 인증서를 내밂
                                    → JVM 검증 통과 → 공격자가 중간에서 모든 내용을 보고 고친 뒤 중계
    ```
    - 공격자가 노출된 개인키로 원하는 도메인의 가짜 인증서 만들기
    - 우리 서버 <-> 상대 서버 사이 통신경로에 끼어들기 (DNS 응답 조작, 네트워크 장비/프록시에서의 ARP 스프링, BGP 하이재킹)
    - JVM은 끼어든 공격자에게 http 요청을 그대로 보내줌

- **어떤 문제로 이어지는가?**
  - 비밀값 탈취: 헤더에 실린 API 키, client secret
  - 개인정보 유출: 요청/응답 본문에 민감 정보. 메시지 내용등
  - 요청/응답 변조: 응답 준게 jar 파일이 있는데 이게 ㄹㅇ 맛탱이간 라이브러리 일수도 있겠다...
  - 인증 우회, 코드 실행/공급망 (백도어에 악성 jar 주입)
