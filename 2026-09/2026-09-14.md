## qdrant point
*참고: https://qdrant.tech/documentation/manage-data/storage/*
*참고: https://qdrant.tech/articles/immutable-data-structures/*

**문제**
- Qdrant point에 key-value 하나 넣는건데 왜 이렇게 오래걸리지?

**용어 정리**
- 컬렉션: 저장하는 테이블 같은거
- 샤드: 컬렉션의 포인트를 수평적으로 분산
- 세그먼트: 하나의 컬렉션 안에 있는 데이터는 세그먼트로 나눈다 (그 자체로 완결된 작은 벡터 DB)
  - vector, payload, index, id mapper, relationship, internal/external id
  - 벡터 저장소, 페이로드 저장소, HNSW 인덱스, payload 인덱스, 외부id-내부번호매칭표 가짐
    - HNSW(Hierarchical Navigable Small World): 고차원 벡터 데이터에서 근사 최근접 이웃 빠르게 찾기 위한 알고리즘
    - 이건 한건씩 고치기 어려워서, 세그먼트 단위로 통째로 다시 빌드

**사유**
- Qdrant에는 세그먼트라는 개념이 있다. 스토리지나 인덱스 사용하는 것에 따라, `appendable` / `non-appendable` 이 있다
  - `appendable`: 더하고, 삭제하는게 자유로움
  - `non-appendable`: 읽고, 삭제만 가능

- 따라서, `non-appendable`에 갱신 요청이 오면 복사해서 옮기고, 예전 point는 삭제 표시
  - 내부적으로 qdrant는 이 경우에, copy-on-write 오퍼레이션을 한다. 

- 내부적으로 불변 구조를 차용함으로써 Qdrant는 메모리 usage를 낮추고, 캐싱, prefetching, prediction 같은것을 최적화함
